\sectionline{1. The idea behind the code}
The original bigram only considers the immediately preceding word. A trigram also considers the word before that, so in principle it can learn more specific question patterns. The downside is that exact three-word combinations appear less often, especially with a small dataset. I therefore did not use a plain trigram by itself: I combined unigram, bigram and trigram probabilities so that the model can still assign some probability when a particular trigram is rare or unseen.

=0.15P_{\rm uni}(w_i)+0.35P_{\rm bi}(w_i\mid w_{i-1})
+0.50P_{\rm tri}(w_i\mid w_{i-2},w_{i-1}).$
\end{center}

The weights \textbf{(0.15, 0.35, 0.50)} were chosen as fixed starting values; I did \textbf{not} optimise them on validation examples. Each component uses add-$k$ smoothing with \textbf{$k=0.1$}, so an unseen combination does not receive zero probability.

In the script, I first prepare the shared Korean questions and map uncommon words to \texttt{<UNK>}. I then count individual tokens, bigrams and trigrams from training data. The probability functions use these counts, and the evaluator applies all three models to the same validation sequences. The code also runs sanity checks and saves scores for each question in a CSV. No neural network or pretrained language model is involved here.

\sectionline{2. Data and evaluation setup}
\begin{itemize}
\item \textbf{Data:} 2,422 Korean training questions and 356 Korean validation questions, loaded from the group's shared dataset. We do not use context passages for this task.
\item \textbf{Tokenisation:} Split each question on whitespace, matching the existing bigram experiment. Keep a token only if it appears at least twice in training; all other words become \texttt{<UNK>}.
\item \textbf{Vocabulary:} 1,126 prediction tokens, including \texttt{<UNK>} and \texttt{<EOS>}. A beginning marker (\texttt{<BOS>}) is used only as history, not as a prediction target; the trigram gets two beginning markers.
\item \textbf{Metric:} Corpus-level per-token perplexity, calculated from all target log probabilities combined. We score each question's words and one \texttt{<EOS>}, but not the beginning markers: \textbf{1,729 text tokens + 356 EOS = 2,085 scored tokens}. Lower perplexity is better.
\end{itemize}

## Week 38 — Korean Language Modelling

In Week 38, we did something different from W36 and W37.

Instead of trying to find answers to questions, **we tried to build a language model that predicts how likely a sequence of words is.**

For this experiment, we focused only on Korean questions.

### 1. What did we do?

We started with the existing **bigram model**, which predicts the next word based on the previous word.

For example, suppose we have:

> What is the capital of ...

A bigram model predicts the next word using only the immediately preceding word, *of*.

We wanted to see whether looking at more context would improve predictions.

So we implemented an **interpolated trigram model**.

It combines three approaches:

- **Unigram:** Predicts a word without considering previous words.
- **Bigram:** Considers one previous word.
- **Trigram:** Considers two previous words.

Instead of relying entirely on trigrams, we combined probabilities from all three models using fixed weights.

Our hypothesis was that considering two previous words would help the model better predict Korean question patterns.

### 2. What did we find?

We trained using 2,422 Korean questions and evaluated on 356 validation questions.

Our results were:

| Model | Perplexity |
|---|---:|
| Unigram | 46.58 |
| Bigram | **24.36** |
| Interpolated trigram | 26.70 |

**Perplexity measures how surprised a language model is by the actual words. Lower is better.**

Interestingly, our interpolated trigram performed worse than the simpler bigram.

So our original hypothesis was not supported.

One possible reason is that we had relatively little training data. The trigram model needs to learn combinations of three words, which are less frequent than combinations of two.

### 3. What interesting things did we discover?

We looked at questions with the highest and lowest perplexities.

One surprising finding was that **38.29% of validation question tokens were mapped to `<UNK>`**, meaning they were outside our training vocabulary.

Some questions achieved extremely low perplexity even though every original word had been replaced with `<UNK>`.

For example, a question about how long an Etruscan dynasty ruled Rome had a perplexity of just 3.95, even though all six tokens were unknown.

This means the model wasn't necessarily understanding or accurately predicting the original Korean words. It was predicting patterns involving the unknown-token symbol.

We also noticed that questions using familiar structures, such as *"What is the largest..."*, often had low perplexity.

### 4. How you can explain W38 to your teammates

> In Week 38, we worked on Korean language modelling. We already had a bigram model, so I implemented an interpolated trigram to see whether considering two previous words would improve predictions. **The key takeaway:** W38 wasn't about extracting answers. It was about predicting word sequences and understanding why a more complex language model might not outperform a simpler one.

\sectionline{1. The idea behind the code}
The original bigram only considers the immediately preceding word. A trigram also considers the word before that, so in principle it can learn more specific question patterns. The downside is that exact three-word combinations appear less often, especially with a small dataset. I therefore did not use a plain trigram by itself: I combined unigram, bigram and trigram probabilities so that the model can still assign some probability when a particular trigram is rare or unseen.

\begin{center}
$P(w_i\mid w_{i-2},w_{i-1})
=0.15P_{\rm uni}(w_i)+0.35P_{\rm bi}(w_i\mid w_{i-1})
+0.50P_{\rm tri}(w_i\mid w_{i-2},w_{i-1}).$
\end{center}

The weights (0.15, 0.35, 0.50) were chosen as fixed starting values; I did not optimise them on validation examples. Each component uses add-$k$ smoothing with $k=0.1$, so an unseen combination does not receive zero probability.

In the script, I first prepare the shared Korean questions and map uncommon words to \texttt{<UNK>}. I then count individual tokens, bigrams and trigrams from training data.     import torch
    from transformers import AutoTokenizer, AutoModelForTokenClassification

    if not Path(model_dir).is_dir():
        raise FileNotFoundError(f"W37 model checkpoint not found: {model_dir}")
    device = torch.device("mps" if torch.backends.mps.is_available() else "cpu")
    print(f"W37 device: {device}")
    tokenizer = AutoTokenizer.from_pretrained(model_dir, use_fast=True)
    model = AutoModelForTokenClassification.from_pretrained(model_dir).to(device)
    model.eval()
    label_to_id = model.config.label2id
    B, I = label_to_id.get("B-ANS", 1), label_to_id.get("I-ANS", 2)
    predictions = []
    for number, row in enumerate(rows, start=1):
        context = row["context"]
        batch = tokenizer(row["question"], context,
                          truncation="only_second", padding="max_length",
                          max_length=384, return_offsets_mapping=True,
                          return_tensors="pt")
        sequence_ids = batch.sequence_ids(0)
        offsets = batch.pop("offset_mapping")[0].tolist()
        inputs = {k: v.to(device) for k, v in batch.items()}
        with torch.inference_mode():
            logits = model(**inputs).logits[0].cpu()
        labels = logits.argmax(dim=-1).tolist()
        b_probs = logits.softmax(dim=-1)[:, B]
        indices = [i for i, sid in enumerate(sequence_ids)
                   if sid == 1 and offsets[i][1] > offsets[i][0]]
        best_span, best_score = None, float("-inf")
        for pos, i in enumerate(indices):
            if labels[i] != B:
                continue
            last = pos
            while last + 1 < len(indices) and labels[indices[last + 1]] == I:
                last += 1
            score = b_probs[i].item()
            if score > best_score:
                best_score = score
                best_span = (offsets[i][0], offsets[indices[last]][1])
        predictions.append(context[best_span[0]:best_span[1]] if best_span else "")
        print(f"W37 evaluated {number}/{len(rows)}: {row['id']}")
    return predictions

# Calculate model-level and paired-example performance metrics.
def summarize(records):
    summaries = []
    for model in sorted({r["model"] for r in records}):
        group = [r for r in records if r["model"] == model]
        pair_ids = sorted({r["pair_id"] for r in group})
        a = [r for r in group if int(r["answerable"]) == 1]
        u = [r for r in group if int(r["answerable"]) == 0]
        pair_success = sum(all(r["exact_match"] == 1 for r in group if r["pair_id"] == pair)
                           for pair in pair_ids)
        class_f1 = []
        for label in [0, 1]:
            tp = sum(int(r["answerable"]) == label and r["predicted_answerable"] == label for r in group)
            fp = sum(int(r["answerable"]) != label and r["predicted_answerable"] == label for r in group)
            fn = sum(int(r["answerable"]) == label and r["predicted_answerable"] != label for r in group)
            class_f1.append(2 * tp / (2 * tp + fp + fn) if (2 * tp + fp + fn) else 0.0)
        summaries.append({
            "model": model, "n": len(group),
            "overall_em": sum(r["exact_match"] for r in group) / len(group),
            "overall_token_f1": sum(r["token_f1"] for r in group) / len(group),
            "answerable_em": sum(r["exact_match"] for r in a) / len(a),
            "answerable_token_f1": sum(r["token_f1"] for r in a) / len(a),
            "unanswerable_em": sum(r["exact_match"] for r in u) / len(u),
            "unanswerable_token_f1": sum(r["token_f1"] for r in u) / len(u),
            "answerability_macro_f1": sum(class_f1) / 2,
            "fully_correct_pairs": pair_success,
        })
    return summaries

def read_challenge(path):

    for row in rows:

            raise ValueError("Challenge record has missing required fields")

        if row["id"] in ids:
            raise ValueError(f"Duplicate ID: {row['id']}")

        ids.add(row["id"])
        pairs[row["pair_id"]].append(row)

        if row["lang"] not in {"ar", "ko", "te"}:
